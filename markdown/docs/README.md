## Documentation Structure

### Safety Case Documentation (`safety_case/`)

Safety case artifacts and templates for ISO 26262/ISO 13849 compliance readiness:

- **outline.md** - Safety case outline for AGV/AMR indoor logistics operations
- **functional_safety_plan.md** - Repository-level functional safety activities and roles
- **safety_manual.md** - Integration constraints for safety-relevant mobile robot stacks
- **traceability_matrix.md** - Hazard-to-control mapping and requirement traceability
- **assumptions_register.md** - System assumptions and dependencies
- **residual_risk_register.md** - Residual risk assessment and mitigation
- **iso26262_iso13849_crosswalk.md** - Cross-reference between safety standards
- **iso_3691_4_clause_matrix.md** - ISO 3691-4 clause conformance matrix
- **tool_confidence_register.md** - Tool classification and confidence levels
- **change_impact_assessment_template.md** - Template for analyzing change impacts
- **verification_protocol_template.md** - Template for verification protocols
- **release_safety_evidence_checklist.md** - Release evidence checklist
- **vv_strategy.md** - Verification and validation strategy
- **misra_compliance_tools.md** - MISRA compliance tools and certification path

### Diagnostics Documentation (`diagnostics/`)

Integration guides for diagnostic and monitoring systems:

- **watchdog_integration_guide.md** - Guide for integrating watchdog systems

## Purpose

These documentation files provide:

1. **Safety Case Scaffolding** - Process and evidence templates for ISO 26262/ISO 13849 readiness
2. **Integration Guidance** - Technical documentation for system integration
3. **Compliance Support** - Standards crosswalks and compliance checklists
4. **Process Documentation** - Safety processes and verification strategies

## Important Notes

### Not Formal Certification

The safety case artifacts in this repository provide **process scaffolding and evidence templates** for ISO 26262/ISO 13849 readiness. Formal compliance requires:

- Project-specific system integration evidence
- Independent assessment and certification
- Organizational process records
- Complete safety case development
- Third-party certification body approval

## Documentation Standards

### Safety Case Documentation

Safety case documents should:

- Use clear, unambiguous language
- Include specific requirement IDs where applicable
- Provide traceability to code and tests
- Follow established templates
- Be reviewed for technical accuracy

### Technical Documentation

Technical guides should:

- Include practical examples
- Provide step-by-step instructions
- Address common issues and troubleshooting
- Reference relevant safety standards
- Be tested for accuracy
