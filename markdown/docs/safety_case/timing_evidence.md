# Timing Evidence — safety_core

Measured latency distributions for safety-critical operations. Generated by
`benchmarks/safety_core_benchmarks` (no external dependencies); the CI
`benchmarks` job re-runs it every build with loose regression budgets
(~20-50x typical) and uploads JSON evidence as a build artifact.

## Method

- `std::chrono::steady_clock` around each call; 50k–100k iterations plus 10%
  warmup; per-operation mean / p50 / p95 / p99 / max.
- Release build (`-O3`), no sanitizers, x86-64 shared runner class.
- Budgets gate on **max** (not p99) so even the tail stays bounded.
- Caveat: shared-CI numbers are orders of magnitude, not target WCET. On the
  deployment platform, re-run the same binary under the target scheduler for
  certified figures.

## Headline claim

**Critical monitor event → latched SafeStop: worst observed 3.7 µs** (p99
0.44 µs). The escalation path performs no dynamic allocation, no locking
beyond atomics, and a single bounded `snprintf`; its timing is dominated by
atomic stores, which is consistent with the bounded-latency design goal.

## Reproducing

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DSAFETY_CORE_ENABLE_SANITIZERS=OFF
cmake --build build --target safety_core_benchmarks
./build/safety_core_benchmarks --iterations 50000          # table + budgets
./build/safety_core_benchmarks --iterations 50000 --json   # machine-readable
```
